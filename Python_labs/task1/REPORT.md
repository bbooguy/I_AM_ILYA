# Отчёт: проверка устойчивости сервера

Ниже — 5 "плохих" запросов, которые были протестированы, и что вернул сервер
в каждом случае. После всех них выполнен контрольный `GET /users`, который
подтверждает, что процесс сервера не завершился аварийно и продолжает
отвечать (см. пункт 6).

## 1. Запрос к несуществующему пользователю
```
GET /users/user99
```
Ответ:
```
404 Not Found
{"error": "Пользователь не найден"}
```

## 2. Запрос к несуществующему маршруту
```
GET /foo
```
Ответ:
```
404 Not Found
{"error": "маршрут не найден"}
```

## 3. POST с "битым" (обрезанным) JSON в теле
```
POST /users/user1/score
Body: {"score":            <- JSON не закрыт
```
Ответ:
```
400 Bad Request
{"error": "невалидный JSON"}
```

## 4. Неверный тип данных в поле score
```
POST /users/user1/score
Body: {"score": "abc"}
```
Ответ:
```
400 Bad Request
{"error": "score должен быть числом"}
```

## 5. Неподдерживаемый HTTP-метод
```
DELETE /users
```
Ответ:
```
405 Method Not Allowed
{"error": "метод не поддерживается"}
```

## Дополнительно протестировано
- `POST /users/user1/score` без тела (`Content-Length: 0`) -> `400 {"error": "поле score обязательно"}`
- Обрыв соединения клиентом посреди отправки тела (клиент заявил `Content-Length: 100`,
  отправил 9 байт и закрыл сокет, не дожидаясь ответа) -> сервер поймал
  `BrokenPipeError`/`ConnectionResetError` при попытке ответить, залогировал
  это и продолжил работу как ни в чём не бывало.

## 6. Доказательство, что сервер не упал

Контрольный запрос сразу после всех сбоев выше:
```
GET /users
```
Ответ:
```
200 OK
{"user1": {"name": "Алексей", "game": "Dota 2", "level": 42, "score": 15820, "playtime_hours": 210},
 "user2": {"name": "Мария", "game": "Valorant", "level": 30, "score": 9870, "playtime_hours": 95},
 "user3": {"name": "Игорь", "game": "CS2", "level": 55, "score": 21000, "playtime_hours": 340}}
```
Счёт `user1` (15820 = 15320 + 500) отражает успешный запрос из `client.py`,
выполненный до сбоев — значит, между сбойными запросами сервер тоже не терял
состояние. Процесс сервера (`server.py`) всё это время оставался запущенным
на одном и том же порту без перезапуска.

## Как воспроизвести
1. В одном терминале: `python3 server.py`
2. В другом терминале по очереди:
   - `python3 client.py` — обычные и один некорректный запрос
   - `python3 edge_cases.py` — битый JSON, пустое тело, обрыв соединения
     + контрольный `GET /users` в конце
