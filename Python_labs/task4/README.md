# ДЗ 4. Защита банковского сервера

Доработка сервера из ДЗ-3 по [заданию](https://github.com/Kulikova-A18/python-iu8-13M-2026-2027/blob/main/dz-4/readme.md).

## Запуск на Mac

Нужны Docker Desktop, Python 3.10+ и Git. Откройте Docker Desktop, затем в Терминале:

```bash
cd ~/Documents/dz-4
python3 setup.py
docker compose up --build -d --wait
```

`setup.py` создаёт случайные пароли в `.secrets`. Существующие файлы он не заменяет. Контейнер доступен только с этого Mac по `127.0.0.1:9999`. База хранится в отдельном Docker volume, исходники и папка ДЗ-3 в контейнер не монтируются.

Посмотреть состояние и журнал:

```bash
docker compose ps
docker compose logs --tail 30 bank
```

Для работы с сервером:

```bash
python3 bank_client.py alice
```

Можно ввести `BALANCE`, `TRANSFER 3 10.00 проверка`, `HISTORY`, `QUIT`. Клиент сам читает пароль из `.secrets` и добавляет поля защиты перевода. Для администратора: `python3 bank_client.py admin`; разрешены только `ADMIN USERS` и `ADMIN STATS`.

Не более пяти попыток входа в минуту по IP и логину, в том числе успешных. Если лимит достигнут, подождите минуту. Не добавляйте `.secrets` в Git. Пароли применяются при создании новой базы: замена файлов сама по себе не меняет пароли в существующей базе.

Остановить сервер с сохранением данных:

```bash
docker compose down
```

## Что изменено

- MD5 заменён на scrypt с индивидуальной солью и сравнением через `compare_digest`.
- Убраны встроенные пароли и `fake_sql`. SQLite-запросы используют параметры.
- Сумма перевода положительная, конечная, максимум с двумя десятичными знаками. В базе суммы хранятся в копейках, переводы самому себе запрещены.
- Проверка средств, изменение двух балансов и запись перевода выполняются одной транзакцией SQLite.
- Обычный пользователь видит только свою историю. Административная команда не принимает SQL и не выдаёт хеши паролей.
- Для перевода нужны одноразовый nonce текущего соединения и уникальный идентификатор запроса. Повторный id хранится в БД и отклоняется даже после перезапуска.
- Ограничены попытки входа, частота команд, размер команды и число соединений. У чтения всей команды есть общий таймаут, который не продлевается каждым байтом.
- Логи содержат события входа, подключения, отклонения и номера переводов. Пароли и полные команды не записываются.
- В Docker используется непривилегированный пользователь, read-only корневая файловая система, ограничения памяти/CPU/процессов и отключённые capabilities. Базовый образ закреплён по digest.

## Проверка защиты

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m unittest -v test_server
```

Тесты создают временные базы и локальные порты. Они не меняют базу запущенного контейнера и не запускают массовую DoS-атаку. Проверяются вход, SQL-подобный ввод, права, суммы, гонка переводов, повтор запроса, ограничения соединений и чтения, TCP-разбиение команд, логи и сохранение данных.

## Изменение протокола

Приветствие и каждый ответ занимают одну строку. Пример нового перевода:

```text
NONCE
TRANSFER <to_id> <amount> <request_id> <nonce> [comment]
```

`request_id` — 32 шестнадцатеричных символа, `nonce` — 64. Nonce выдаётся сервером и привязан к текущему авторизованному соединению. Старые переводы без этих полей намеренно отклоняются.

В истории и ADMIN USERS суммы в копейках; BALANCE выводит денежную сумму с двумя знаками. История ограничена последними 100 записями.

## Ограничения

Это учебный локальный сервер. В протоколе нет TLS: нельзя открывать порт в интернет и передавать реальные пароли. Для удалённого использования нужен TLS. Nonce не защищает от злоумышленника, который уже получил пароль и сам проходит вход.

Ограничения соединений и Docker снижают риск исчерпания ресурсов, но не гарантируют защиту от любой DoS-атаки. Лимиты входа хранятся в памяти и сбрасываются при перезапуске; блокировка может временно затронуть других пользователей с одного IP.

Старый скрипт подмены `bank_db.json` не влияет на SQLite. Права и отдельный volume ограничивают доступ к хранилищу, но не защищают от владельца Docker, root или пользователя, получившего доступ к самой SQLite-базе. Шифрование или подпись базы здесь не реализованы.
