# ДЗ 4. Что исправлено и как проверено

Сервер из ДЗ-3 доработан и запущен в Docker на Mac. Исходная версия ДЗ-3 не менялась.

## Изменения

| Проблема | Исправление | Проверка |
|---|---|---|
| MD5 и простые встроенные пароли | scrypt с отдельной солью для каждого пользователя, случайные начальные пароли в файлах secrets | Вход с верным паролем работает, старый `qwerty` не подходит; соли различаются |
| Обход входа через `fake_sql` | Самодельный SQL убран, поиск пользователя идёт параметризованным запросом SQLite | SQL-подобный логин не даёт доступа |
| Произвольные запросы ADMIN | Разрешены только USERS и STATS; в ответах нет соли и хеша | Обычный пользователь получает отказ, SQL администратора тоже отклоняется |
| Отрицательные суммы и перевод себе | Валидация суммы и получателя | Отрицательная, нулевая, бесконечная сумма, лишняя точность и перевод себе отклоняются |
| Гонка переводов | BEGIN IMMEDIATE, условное списание, оба баланса и запись перевода в одной транзакции | Из 20 переводов по 400 проходят ровно 12 при балансе 5000; остаток 200, общая сумма денег сохранена |
| Частично выполненный перевод | Ошибка записи откатывает транзакцию | При искусственной ошибке добавления записи оба баланса остаются прежними |
| Чужая история | Проверка владельца или роли admin | HISTORY чужого пользователя возвращает отказ |
| Повтор команды | Одноразовый nonce соединения и уникальный id запроса в БД | Повтор той же команды, повтор id в новом соединении и после открытия базы заново не списывают деньги |
| Подбор пароля | Лимит входов по IP и логину, включая новые соединения | Шестая попытка за минуту отклоняется |
| Медленная/бесконечная команда | Общий таймаут чтения строки, ограничение длины | Незавершённая и слишком длинная команда приводят к закрытию соединения |
| Большое число подключений | Не более 32 активных соединений, не более 16 с IP | В тесте при уменьшенном лимите лишнее соединение отклоняется, обслуживаемые остаются рабочими |
| Некорректный ввод и TCP-разбиение | Чтение до перевода строки с сохранением остатка буфера | Ошибочные команды отклоняются; разделённые и склеенные TCP-команды читаются правильно |
| Пароли в логах | Журналируются события, а не полные команды | Тест проверяет отсутствие пароля в логах входа |
| Подмена bank_db.json | Данные перенесены в SQLite в отдельном volume с правами 600 | Создание постороннего JSON не меняет баланс; база сохраняет переводы после повторного открытия |

Последняя строка не означает защиту от владельца Docker или root: имея доступ к SQLite-файлу, его можно изменить. Защита здесь основана на правах доступа и отделении хранилища от исходников.

## Docker

- Образ успешно собран и сервер запущен через `docker compose up -d --wait`.
- Healthcheck прошёл: статус `healthy`.
- Порт опубликован только на `127.0.0.1:9999`.
- Процесс работает под UID 10001; права файла базы — `600`.
- Корневая файловая система read-only; запись разрешена в volume базы и временный tmpfs.
- Отключены capabilities, запрещено повышение привилегий; ограничены память, CPU, процессы и размер логов.
- На реальном сервере проверены вход, запрет чужой истории и перевод 0,01. После этой проверки у alice 4999,99, у bob 100,01. Автотесты используют отдельные временные базы.

## Semgrep

Semgrep 1.181.0, официальные правила коммита `17e31e11ebac99fb7dfe1cd288f7a32151b6f3f9`.

| Цель | Набор правил | Результат |
|---|---|---|
| main.py, bank_client.py, setup.py | python | 0 срабатываний, 0 ошибок анализа |
| Dockerfile | dockerfile | 0 срабатываний, 0 ошибок анализа |

При первой проверке Dockerfile правило `dockerfile-source-not-pinned` указало на образ без digest. Образ закреплён по SHA-256, после чего проверка выполнена повторно. Итоговые JSON сохранены в `semgrep-python.json` и `semgrep-docker.json`.

## Итог

Внутри Docker прошли 16 тестов; вывод сохранён в `test-results.txt`. Исправлены проблемы паролей, прав доступа, сумм, повторов запросов и одновременных переводов. Добавлены логирование и ограничения ресурсов.

Нулевой результат Semgrep не доказывает отсутствие всех ошибок. Сервер предназначен для локальной учебной работы: TLS не добавлен, поэтому публиковать его в интернете нельзя. Лимиты уменьшают последствия перегрузки, но не дают полной защиты от DoS. Произвольное изменение базы владельцем системы также не предотвращается.
