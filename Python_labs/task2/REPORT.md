# Отчёт: проверка устойчивости сервера

Проверки выполнены 6 октября 2026 года с Python и Pydantic 2.13.5.
Использован один экземпляр HTTPServer без перезапуска, на свободном локальном
порту. Для обычного воспроизведения запустите `python3 server.py`, затем
в другом терминале `python3 edge_cases.py` из этого каталога.

## Основные плохие запросы

| Запрос | Код | Поле error в JSON-ответе |
| --- | --- | --- |
| `GET /users/user99` | 404 | Пользователь не найден |
| `GET /foo` | 404 | маршрут не найден |
| `POST /users/user1/score`, тело `{"score":` | 400 | невалидный JSON |
| `POST /users/user1/score`, тело `{"score": "abc"}` | 400 | нужен объект с полем score: целое неотрицательное число |
| `DELETE /users` | 405 | метод не поддерживается |

Дополнительно проверены: пустое тело (400), отсутствие score, JSON-массив,
null и число вместо объекта (400); строка `"100"`, bool, дробь и отрицательное
значение score (400); OPTIONS и произвольный CUSTOM (405); GET на маршруте
обновления и POST на маршрутах чтения (405); неизвестные POST-маршрут и
пользователь (404).

## Обрыв соединения

Клиент заявил Content-Length: 100, отправил только `{"score": 999}` и закрыл
сторону отправки. Сервер вернул 400 с ошибкой «тело запроса не получено полностью».
Даже синтаксически правильное, но неполное по заявленной длине тело не обновило
счёт. Затем клиент отправил только `{"score":` и полностью закрыл сокет.
Сервер продолжил принимать запросы. Если отправить ответ уже невозможно,
ConnectionError/TimeoutError перехватываются при записи ответа; доставить JSON
отключённому клиенту невозможно. На чтение установлен таймаут 5 секунд, чтобы
незавершённая отправка не занимала сервер бесконечно.

## Доказательство сохранения работы и состояния

Перед ошибками успешный POST с `{"score": 500}` изменил score user1 с 15320 на
15820. После каждого обычного случая контрольный GET /users вернул 200.
После обоих обрывов GET /users/user1 вернул 200 и те же данные со score 15820.
Все утверждения edge_cases.py прошли, включая проверку неизменности данных
после ошибочных запросов. Итоговый вывод:

```text
Все проверки пройдены; сервер отвечает после ошибок и обрыва соединения.
```

## Реализация

Данные — `dict[str, UserStats]`; UserStats и ScoreUpdate наследуются от
Pydantic BaseModel. Числовые поля имеют ge=0 и строгий целочисленный тип.
Маршруты разбираются через split без regex. Клиент вводит метод, путь и
необработанное JSON-тело отдельно, поэтому может отправлять ошибочные запросы.
Сервер учебный, однопоточный; данные существуют только до перезапуска.
